# CloudStudio 操作说明

仓库已核实：**https://github.com/KK0341/coin-anomaly-research**（Private，main）。本地根目录 `E:\异常检测`。根 README 是远程原有文件，保持原样。本次只同步代码与部署工具，不上传数据、不启动训练。

## 1. 首次克隆与依赖

进入课程分配的 GPU 空间，确认持久盘实际路径。GitHub 授权由你手动完成，可使用课程已有 Git 集成或 `gh auth login`（若已安装）；不要把 Token 写在命令或仓库里。使用实际持久目录替换下面的占位路径。

```bash
git clone https://github.com/KK0341/coin-anomaly-research.git
cd coin-anomaly-research
nvidia-smi
bash cloudstudio/setup.sh
source .venv-cloud/bin/activate
python cloudstudio/check_env.py
python -m pip check
```

安装脚本复用镜像的 torch/torchvision，其他依赖装进独立 venv。如果没有可用 CUDA PyTorch，按 [依赖说明](README.md#2-云端环境) 安装与驱动匹配的版本，再检查。先不执行训练。A1 已适配，其他实验仍需核对路径、输入和依赖。

## 2. 数据和大型权重的独立传输

完整运行资产统一放在 Git 仓库外的持久盘：

```text
/YOUR_PERSISTENT_DIR/coin/
  splits/训练集.csv、验证集.csv、测试集.csv
  images/数据采集/民国中央/...       # 对应 E:\钱币鉴别 的子目录
  assets/A0/模型/convnext_tiny-983f1562.pth
  runs/A1/2026-11-15/run-001/        # 每次新训练使用不同目录
  transfers/                        # 压缩包/校验清单，与 Git 隔离
```

本次不传输任何数据。以后按选定实验仅传必要资产，保留原 CSV 字节、目录层级和文件名：

- 小批资产：在 CloudStudio 打开持久目录，拖拽上传文件/文件夹。大目录可先在本地**新建**压缩包再上传，不移动原文件。
- 大规模数据和 checkpoint：采用独立的腾讯云 COS 私有桶（用户自行开通/授权，确认费用）或课程提供的持久存储传输渠道；配置工具凭据时只用外部凭据存储/临时环境，不入库。网络中断时使用相应工具的续传能力。
- 下载权重：CloudStudio 文件面板下载 best.pt、last.pt；整次运行可在持久盘新建归档后下载。不要放进普通 Git，也不要把私有桶的预签名 URL 写进报告。这里未开通 COS 或产生传输费用。
- 传输前后比较 SHA256：Windows `Get-FileHash -Algorithm SHA256 -LiteralPath '文件路径'`；Linux `sha256sum '文件路径'`。路径检查仅验证文件存在，不能代替逐文件内容校验。

文件面板方式参见 [腾讯官方文件上传/下载说明](https://cloud.tencent.com/document/product/1039/131809)。

## 3. 检查、启动、停止与恢复

以下检查不训练，输出目录不可位于仓库或数据目录内部：

```bash
BASE=/YOUR_PERSISTENT_DIR/coin
RUN="$BASE/runs/A1/$(TZ=Asia/Shanghai date +%F)/run-001"
ARGS=(--splits "$BASE/splits" --images "$BASE/images" --assets "$BASE/assets" --output "$RUN" --gpu 0)
python cloudstudio/run_a1.py "${ARGS[@]}"
```

以后确认开始正式实验时，在 tmux 会话内运行（可先 `tmux new -s coin-a1`，若已提供 tmux）：

```bash
python -u cloudstudio/run_a1.py "${ARGS[@]}" --execute
```

新运行要求空目录，训练会打印 `TRAIN_PID=...`。单卡与 GPU 检测不改变原 batch/模型/优化器。完成后仍执行原 A1 验证与测试流程。

停止：前台按 **Ctrl+C 一次**，或另一终端 `kill -TERM 实际TRAIN_PID`。适配器等待原训练代码完成当前轮次并原子保存 last.pt 后退出，可能需要等待一整轮。停止请求若发生在最终评估中，会等待评估自然结束；不要用 `kill -9` 或直接关闭空间当作安全停止。强制停机只能从上个已完整保存的轮次恢复。

恢复（相同 RUN、源码和配置）：

```bash
python -u cloudstudio/run_a1.py "${ARGS[@]}" --execute --resume
```

保留 last.pt 和 best.pt。每完整轮保存模型、优化器、scaler、scheduler、历史和早停状态；原恢复逻辑按轮次重设种子，不能保证跨硬件逐位复现。离开前确认持久盘保留政策并备份权重。

## 4. 轻量结果回传 GitHub

先停止训练，再同步 main；不要在运行中 pull。遇到分叉/冲突时停止并人工合并，禁止强推、reset 或覆盖结果。以下文件路径以实际产物为准：

```bash
git pull --ff-only
python cloudstudio/results.py export --run "$RUN" --experiment A1 \
  --file cloud_run.json --file 结果/history.json \
  --file 结果/test_metrics.json --file 结果/training_curves.png
python cloudstudio/audit_sync.py
git add -- cloud_results
python cloudstudio/audit_sync.py --staged
git diff --cached --stat
git diff --cached
git commit -m "Add A1 cloud experiment results"
git push origin main
```

如云端 Git 缺提交身份，手动设置自己的 `git config user.name` / `git config user.email`；身份不等于登录授权。单文件上限 2 MiB，每包上限 20 MiB、20 文件、8 图。只明确选择指标、报告和图表；不要选逐样本数据或完整预测。导出不自动 commit/push，必须审查内容。

结果包使用 `cloud_results/实验名/北京时间日期/时间-随机ID/`，不会覆盖旧包。包内有 SHA256 和导出时 Git 提交；训练来源以 cloud_run.json 中源码/配置哈希为准，导出提交不冒充训练提交。

## 5. 本地接收与继续开发

```powershell
Set-Location E:\异常检测
python cloudstudio/results.py receive --pull
```

这会执行 `git pull --ff-only`，再校验包并**复制**至 `E:\异常检测\云端实验结果\实验名\日期\运行ID`。一致的已接收包跳过，有差异时报错；不覆盖、不移动原算法实验结果。若已手动 pull，运行不带 `--pull` 的 receive 即可。完整权重通过上一节的独立渠道下载到对应运行目录之外的权重备份目录，避免改变已校验的轻量结果包。

本地代码更新继续使用审查、commit、push；后续有意修改原算法时，需更新源文件审计基线并记录实验变更。两个端点并发推送遭拒绝时先检查远程新增内容，正常合并再推送。
